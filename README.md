# 猫狗性格研究所：订单验证码版

买家输入发货消息里的验证码后，可以反复测试猫咪或狗狗。新版验证码为 6 位纯数字，首批已生成 1000 个。此前发出的 `PET-...` 旧码继续有效。

## 部署

Cloudflare Pages 保持框架 `None`、构建命令留空、输出目录 `dist`、根目录留空。仓库根目录需要有 `dist/`、`functions/` 和 `lib/`。生产环境的加密 Secret `PET_CODE_SECRET` 必须与生成码表时使用的私密密钥一致；不要把密钥或原始码表提交到 GitHub。`lib/numeric-code-digests.js` 只存放用密钥计算的摘要，可以随网站部署。

部署后访问 `https://你的域名/api/access`。未输入码时，配置正确的响应是 `{"ok":false,"configured":true}`；未配置 Secret 时返回 503。

## 一单一码

首批数字码保存在卖家本机的私密码表中。每成交一单，取一行尚未发出的码，把实际订单号填入该行，并只把这一枚码发给该买家。买家可以重复使用自己的码。网页本身不会读取小红书订单，也不会自动发货；自动逐单发码需要在小红书或所用发货工具中另行配置。

后续增加码时，使用**同一个** `PET_CODE_SECRET`，运行 `scripts/generate-numeric-codes.mjs <数量> <新的私密 CSV 路径>`。脚本会生成新的码表，并将新码的摘要追加到 `lib/numeric-code-digests.js`；必须重新部署这个摘要文件，新码才会生效。不要重复使用相同的输出文件名，也不要更换 Secret，否则所有旧码都会失效。

## 限制

6 位数字且 1000 个码同时有效，随机猜一次命中的概率约为 1/900；当前版本没有按买家账户绑定，也没有服务端限流。码可以被转发给其他人。现有题目和画像文本位于公开静态文件中，技术用户也可能绕过验证界面。需要更严格的付费控制时，应使用更长的码、限流和服务端结果计算。
